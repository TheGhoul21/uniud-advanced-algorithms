Rabin-Karp — Rolling Hash

Interactive visualizations for Chapter 1 of the Advanced Algorithms notes

How Rabin-Karp Works

The Rabin-Karp algorithm uses hashing to speed up string matching. Instead of comparing every character at every alignment, it computes a hash fingerprint of the pattern and of each length-m window of the text. If the hashes differ, the window cannot match — skip it without any character comparisons.

Key ideas:

  • Hash-based filtering. Compute h(P) once. At each shift s, compute h(T[s..s+m-1]) and compare it to h(P). Only when the hashes agree do we verify character-by-character.
  • Rolling hash. Re-computing the hash from scratch at every position would be just as slow as naive matching. A rolling (incremental) hash lets us update the window hash in O(1) using the formula h_new = (d * (h_old - T[s] * d^(m-1)) + T[s+m]) mod q.
  • Spurious hits. Two different strings can hash to the same value (a collision). When hashes match but the strings differ we call it a spurious hit. The algorithm is still correct because every hash match is verified, but spurious hits add extra work.

The polynomial rolling hash used here is:

\[h(s) = \bigl(s_0 \cdot d^{m-1} + s_1 \cdot d^{m-2} + \cdots + s_{m-1}\bigr) \bmod q\]

with alphabet size d = 256 and a small prime q = 101 (chosen small so you can follow the arithmetic by hand).

Rolling Hash Step-by-Step

This visualization shows how the rolling hash is updated from one window to the next. At each step:

  1. The outgoing character T[s] (red) is removed by subtracting T[s] * d^(m-1).
  2. The running value is multiplied by d (the base shift).
  3. The incoming character T[s+m] (green) is added.
  4. The result is taken mod q.

Comparison with Naive

How many character comparisons does Rabin-Karp need versus naive matching? When the hash function distributes well (few spurious hits), Rabin-Karp verifies only at real matches — vastly fewer character comparisons than the naive approach which must compare at every position.

Try lowering q to a very small prime (e.g. 2 or 3) to see how more collisions increase the character comparison count.
